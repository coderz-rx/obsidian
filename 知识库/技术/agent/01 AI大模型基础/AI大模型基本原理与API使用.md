## 一、AI 基础分类

| 类型 | 核心特征 | 典型应用 |
|------|---------|---------|
| **分析式 AI** | 从已有数据中提取规律、做判断/分类 | 图像识别、推荐系统、风控模型 |
| **生成式 AI** | 基于学习到的模式**创造新内容** | 大语言模型（LLM）、文生图、代码生成 |

> 大语言模型区别于传统搜索引擎：搜索引擎是“检索已有信息”，而大模型能够**生成**从未在训练数据中逐字出现过的回答。

## 二、大模型的训练方式

本节内容偏原理层，视频课中建议**参考专门的原理课笔记**。核心三阶段可简要概括：

1. **预训练（Pre-training）**：海量无标注文本 → 学习语言统计规律与世界知识
2. **有监督微调（SFT）**：高质量对话数据 → 让模型学会按人类偏好回答问题
3. **RLHF / 对齐**：人类反馈强化学习 → 提升安全性、有用性和回答风格

## 三、Token：模型处理文本的最小单位

### 3.1 什么是 Token

- **Token 是大语言模型处理文本的最小单位**。
- 不同模型的分词方式不同，会直接影响：
  - 模型对语言细节的理解能力
  - 上下文长度利用率
  - 计费方式（通常按 token 数计费）

### 3.2 如何观察 Token

- 可视化工具：[https://tiktokenizer.vercel.app](https://tiktokenizer.vercel.app)
- 输入任意文本，可看到不同模型（如 GPT-4、Claude、Qwen 等）是如何切分的。

### 3.3 判断两个模型是否“同款”

关键看：**token 的映射方法是否一致**，即同一个词对应的 token ID 是否相同。

### 3.4 特殊 Token

| 特殊 Token | 含义 | 作用 |
|-----------|------|------|
| `bos` | Begin of Sentence | 句子开始标记 |
| `eos` | End of Sentence | 句子结束标记 |
| `user` | 用户角色 | 标识用户输入 |
| `assistant` | 助手角色 | 标识模型输出 |

> 这些特殊 token 是模型对话格式化的基础，API 调用时通常由 SDK 自动处理。

## 四、控制生成结果的两大参数

### 4.1 Temperature（温度）

- 在模型输出下一个 token 的**概率分布**基础上，调整分布的“平滑度”。
- **值越高**：低概率 token 更容易被选中，生成更有创造性，但可能不连贯。
- **值越低**：高概率 token 权重更大，生成更稳定、更符合训练数据，但更保守。

**常用场景：**

| 场景 | 推荐 Temperature |
|------|-----------------|
| 代码生成、 factual QA、数学推理 | 0.0 ~ 0.3 |
| 通用对话、文案写作 | 0.5 ~ 0.7 |
| 头脑风暴、创意写作、诗歌 | 0.8 ~ 1.2 |

### 4.2 Top P（核采样）

- 设定一个概率阈值 P，从高到低累加所有 token 的概率，直到总和超过 P。
- 模型只在这个“核心词汇表”中选择下一个 token。
- 相比 Temperature，Top P 能**动态调整候选词数量**，避免选中概率极低的离谱词汇。

**二者关系：**

- Temperature 调整“敢不敢冒险”。
- Top P 调整“候选池大小”。
- 通常**组合使用**，例如 `temperature=0.7, top_p=0.9`。

## 五、AI 如何“读取”不同格式的文件

AI 并非像人类一样直接“打开文档”，而是把各种格式**翻译成模型能理解的结构化数据**。

| 文件类型 | 处理方式 | 关键说明 |
|---------|---------|---------|
| **PDF / 扫描件** | OCR 提取文字 → 版式分析 → 转 Markdown | 识别标题层级、段落、表格、双栏混排、图文环绕 |
| **Word / Excel** | 解析底层 XML 结构 | 保留大纲、表格、公式、样式，避免纯文本混乱 |
| **图片** | 多模态视觉编码器（ViT）提取特征 | 与语言模型对齐，实现看图说话、图表理解、手写识别 |
| **音频 / 视频** | ASR 转文本，或提取关键帧按图像处理 | 多模态融合的另一种形式 |

> 核心结论：AI 读取文件的能力 = **格式解析 + 结构化 + 模态对齐**。

## 六、Agent 产品的三种核心能力

现代 AI 应用（Agent）通常会在模型能力基础上，叠加以下三种工程能力：

### 6.1 联网搜索

- 当问题涉及最新信息时，产品识别搜索意图，生成关键词，调用搜索 API。
- 搜索结果作为上下文补充给模型，模型再总结输出。
- **关键认知**：联网不是模型参数更新了，而是模型**使用了外部工具**。

### 6.2 读取文件

- 即第五节所述的多格式解析能力。
- 是产品工程能力，不是模型原生自带。

### 6.3 记忆

- **LLM 本身通常是无状态的**，每次请求都是独立的。
- **短期记忆**：把最近对话历史一并发送给模型。
- **长期记忆**：应用提取用户偏好，存入数据库，后续对话中重新注入。
- **关键认知**：记忆是产品工程能力，不是模型自动永久记住。

## 七、API 使用：从调用到实践

### 7.1 API 调用的本质

- 调用大模型 API 本质上是一个 **HTTP 请求**。
- 输入：prompt / messages + 参数（temperature、top_p 等）。
- 输出：模型生成的文本（token 流或完整文本）。

### 7.2 课程实践案例

课程配套了 6 个 API 调用案例，覆盖了常见场景：

| 序号 | 案例 | 说明 |
|------|------|------|
| 1 | 情感分析 - Qwen | 基础文本分类调用 |
| 2 | 天气 Function - Qwen | Function Calling / 工具调用入门 |
| 3 | 表格提取 - Qwen | 结构化输出与文档理解 |
| 4 | 运维事件处置 - Qwen | 垂直领域应用 |
| 5 | 情感分析 - DeepSeek（阿里代理） | 不同模型/渠道的 API 调用 |
| 6 | 联网搜索 | 搜索工具 + 模型结合 |

> 代码实现详见课程目录 `5-AI大模型原理与API使用/CASE-API使用/` 下的 `.py` / `.ipynb` 文件。

### 7.3 调用时的关键注意点

1. **模型选择**：不同模型擅长领域不同，成本和效果也有差异。
2. **参数配置**：temperature / top_p / max_tokens / system prompt 等会显著影响结果。
3. **上下文管理**：多轮对话需维护 messages 数组，注意 token 消耗。
4. **错误处理**：API 可能限流、超时、返回异常，生产环境需做重试和降级。
5. **成本控制**：按 token 计费，输入 + 输出都算，长上下文和复杂 prompt 会更贵。

## 八、核心认知总结

1. **大模型是生成式 AI 的代表**，区别于搜索引擎的“检索”。
2. **Token 是模型理解语言的底层单元**，分词方式影响效果、长度和成本。
3. **Temperature / Top P 是调节创造性的双杠杆**，组合使用更可控。
4. **AI 读文件 = 多格式解析 + 结构化 + 多模态对齐**，不是直接“看懂”。
5. **Agent 的联网、读文件、记忆都是工程能力**，不是模型原生能力。
6. **API 调用不复杂，核心是把 prompt、参数、上下文管理好用好**。
