## 核心矛盾

单次 LLM 调用耗时长（秒级到几十秒）、吞吐受限、成本高。传统 Web 高并发的思路是"把请求处理快"，而 AI 应用的思路是"请求本身快不了，得想办法扛住、削峰、复用、降级"。

---

## 一、连接层：异步化 + 流式，别让线程干等

这是最基础也最关键的一层。LLM 调用动辄十几秒，如果用同步阻塞模型（一个请求占一个线程），几百并发就会把线程池打满。

- **全链路异步**：Java 侧用 WebFlux / 虚拟线程（JDK21 Loom），Python 用 asyncio。目标是一个线程能挂起成百上千个在途的 LLM 请求，CPU 几乎不占，就等 IO。虚拟线程对存量 Java 代码特别友好，改造成本低。
- **SSE 流式输出**：用户感知到的是"首 token 时间（TTFT）"，不是总时长。开启 streaming 后首字 1 秒内返回，体验上就不卡了，还能顺带做"边生成边展示"。
- **合理超时 + 取消传播**：客户端断连要能级联取消上游 LLM 请求，否则白白烧 token 和占用配额。

## 二、流量层：排队削峰 + 限流，核心是保护后端配额

LLM 后端（无论自建推理还是调 API）的并发/TPM 是硬上限，打超了就是 429。所以要主动管控而不是硬扛。

- **请求排队**：前面放一个队列（内存队列 / MQ），按 LLM 实际处理能力匀速消费。突发流量进队列，平滑地喂给模型。这是 AI 应用和普通服务最大的区别 —— 宁可排队让用户等，也不要雪崩。
- **限流**：不止限 QPS，更要限 token 速率（TPM）和并发在途数，因为 LLM 的瓶颈是 token 吞吐而不是请求数。
- **优先级队列**：区分同步交互（用户在等）与异步批处理（离线跑），前者优先，后者可以慢慢来甚至夜间跑。

## 三、复用层：缓存，ROI 最高的一招

AI 场景重复度往往比想象中高，缓存能直接砍掉大量调用。

- **精确缓存**：相同 prompt → 直接返回历史结果（注意带上温度=0 等前提）。
- **语义缓存**：把 query 向量化，相似问题命中缓存（用向量库做 ANN）。对 FAQ、固定话术类场景命中率很高，但要控好相似度阈值，防止答非所问。
- **Prompt Caching**：主流厂商都支持把长的系统提示、上下文前缀缓存住，命中后既降延迟又省钱（省很多）。如果有大段固定的业务规则 prompt，务必开启。

## 四、模型层：路由 + 降级，不是所有请求都配用最强模型

- **模型路由/分级**：简单任务（分类、抽取、改写）走小模型（如 Haiku 级）又快又便宜，复杂推理才上大模型（如 Opus 级）。用一个轻量分类器或规则做路由，整体吞吐和成本大幅改善。
- **降级策略**：大模型过载/超时时，降级到小模型、降级到缓存结果、或降级到规则/模板兜底。保证"有损可用"好过"直接失败"。
- **多 provider / 多 key 负载均衡**：分散到多个部署或账号，规避单点配额，429 时自动 failover。

## 五、调用层：批处理 + 并发控制

- **批处理（batching）**：自建推理时，把多个请求拼成一个 batch 喂给 GPU（continuous batching，vLLM / TGI 都内建），吞吐能翻好几倍。离线场景还能用厂商的 Batch API（半价但异步）。
- **信号量控制并发**：对每个下游模型维护一个并发上限的信号量，超过就排队，精确匹配后端能力。

## 六、架构层：同步转异步

对于不要求实时返回的场景（生成报告、批量处理），直接改成任务制：提交请求 → 返回任务 ID → 后台异步跑 → 回调/轮询取结果。这样前端完全不阻塞，后端可以从容调度。缺陷巡检、周报这类批处理就很适合这个模式。

## 一个典型的治理组合

落地时通常是叠加使用：

```
用户请求
  → 限流(TPM/并发)
  → 语义缓存命中? → 命中直接返回
  → 入队列(削峰 + 优先级)
  → 模型路由(简单→小模型 / 复杂→大模型)
  → 信号量控并发 → 异步流式调用 LLM
  → 超时/429 → 降级(小模型/缓存/模板兜底)
  → SSE 流式返回首 token
```

配合监控：盯 TTFT、总延迟 P99、队列积压长度、429 比例、缓存命中率、token 消耗，这些才是 AI 应用真正该看的指标。

## 场景细化方向

- **在线交互**（用户实时对话/问答）还是**离线批处理**（巡检、周报生成）为主？
- 后端是**调商用 API** 还是**自建推理集群**？

这两点会显著改变治理重点 —— 在线场景优先做流式 + 缓存 + 路由，离线场景优先做队列 + 批处理 + Batch API。
